# 当前 Agent 对话投递

## 唯一渠道

情绪潮汐的当天卡片只交付到用户启动自动化时所在的 Agent 对话。飞书 CLI 只用于按用户身份读取消息、读写用户私有 Base；禁止用它发送私聊、群消息、机器人消息、图片、文字或 Base 链接。

`recipient_user_id` 仅保留为旧配置的用户归属校验字段，必须等于 Base owner 与当前验证用户，不能当作任何消息接收人。

## 创建自动化前

先确认宿主能够在 17:50 唤醒**同一用户对话**，并在该对话中提供 `present_files`。把自动化绑定到这次安装对话，不能改投到另一条会话、后台任务窗口或外部聊天。

任一能力无法确认时，不创建一个会假装会送达的定时卡片任务；向用户说明 `conversation_delivery_unavailable`，并允许用户日后在支持该能力的对话中手动运行。禁止以飞书私聊作为替代渠道。

## 每日交付顺序

1. 工作日门禁、doctor、消息和表情读取、去标识化、JSON 校验、Base 按日期 upsert 与回读全部完成。
2. 用已校验 JSON 渲染 SVG，再转 PNG。PNG 只含汇总字段，不含原文、聊天名、人员或消息 ID、配置值、模型输入或原始响应。
3. 在 PNG 仍存在时，调用宿主的 `present_files`，把这一个 PNG 贴到当前对话；参数遵从宿主运行时定义，不猜测其他平台的参数或工具名。
4. 在同一 Agent 回复中给出简短文字：文本线索估计、证据边界、一个微小行动、暖心话和自愿校准问题。用户可忽略、修改或暂停。不要附 Base 链接或私有配置值。
5. `present_files` 已返回成功或失败后，再删除本次临时目录。

同一日期的重复运行先依赖 Base 幂等回读确认事实记录；同一自动化唤起只尝试一次卡片交付。重试时保留真实状态，避免把失败伪装成已送达。

## 失败与无证据

- `notify_on_no_evidence=false` 时，"无本人消息"或未通过证据门的日期只写入 Base，不贴卡片、不发文字。
- PNG 渲染或 `present_files` 失败时，保留已回读的 Base 记录，在当前 Agent 对话中说明卡片未能交付；可继续给简短文字，不能改投飞书。
- 对话不可用或不存在 `present_files` 时，标记 `conversation_delivery_unavailable`，不发送飞书消息。
- 只有明确的第一人称即时自伤/他伤意图触发 `human_attention`。停止普通暖心话，在当前对话使用配置中的本地紧急支持信息，建议联系可信赖的人与当地紧急或专业支持；不做风险分级，也不向飞书或第三方升级。
